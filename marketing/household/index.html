One note, two homes. Checklists, headings, lists, and tables round-trip both ways.

The two-app household

Someone you share your life with keeps everything in Apple Notes: the grocery list, the trip plan, the running list of movies. It works for them, and it isn’t going to change. Meanwhile you’ve got a vault, a favorite editor, keybindings you’ve tuned for a decade — and every shared plan lives in the one app where none of that helps you.

icloud-md is the peace treaty. Their notes stay exactly where they are. Yours become files.

It works with notes shared with you

This is the part most tools skip. Notes and folders other people share with you are cloned right alongside your own, each sharer under their own directory. You can edit a note in your partner’s shared folder from your editor, push it, and it shows up on their phone like any other edit. (Their notes never leave their account — you’re syncing your own legitimate access to them.)

How it works

$ icloud-md clone ./notes

Clone once

Sign in through Apple’s own login page — password, 2FA and all. Every note becomes a Markdown file, in the same folders you see in Notes.

$EDITOR "Grocery list.md"

Edit anywhere

They’re ordinary files. Search them, grep them, keep them in git, open them in the editor you already love.

$ icloud-md push

Sync both ways

pull brings down edits from phones and laptops; push sends yours up. Edits from both sides get merged, not clobbered.

It will not eat the grocery list

✓

Real three-way merges. If a note changed on a phone and in your editor, the parts that don’t overlap merge automatically; only genuine collisions ask you to choose.

✓

Verified before every write. Before pushing an edit, icloud-md proves it can rebuild the note byte-for-byte. If it can’t fully understand a note, it leaves it read-only instead of guessing.

✓

Version history built in. Every sync that changes a note snapshots it first — history, diff, and revert can inspect or roll back any past version.

Bring your own editor

Obsidian VS Code vim Emacs iA Writer grep, honestly

Obsidian folks: clone with --filename-as-title and each file is named for its note’s title, the way your vault expects.

Install

# Requires Node.js 20+ npm install -g icloud-md icloud-md clone ./our-notes

Questions a reasonable partner would ask

Will they notice anything changed?

No. Your edits arrive in Notes exactly like edits from another of your devices. Nothing installs on their phone, and their setup doesn’t change at all.

What happens if we both edit the same note at once?

The next pull merges both sets of edits. If you both touched the very same lines, you get standard conflict markers to resolve — the tool never silently picks a winner.

Does formatting survive the round trip?

Headings, lists, checklists, blockquotes, code blocks, links, bold/italic — yes, both directions. Tables too, including cell edits. Notes with things it can’t faithfully round-trip (like photo attachments) stay read-only rather than risk mangling them.

Is this an official Apple thing?

No — see the honest print below. It speaks the same private API Apple’s own iCloud.com Notes page uses, which Apple could change at any time.

The honest print. icloud-md is not an official or supported Apple API — it’s a careful reverse-engineering of the service iCloud.com itself uses. It’s built to refuse rather than corrupt, and it keeps its own version history, but you should still keep your notes folder in git (or another backup), try it on a throwaway note first, and know that Advanced Data Protection accounts aren’t supported.
